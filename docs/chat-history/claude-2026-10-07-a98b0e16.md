## How it works

- A command starts with `*`. Each maps to one task file under `.tfcore/tasks/`; read that file when the command is typed, not before. Read `.tfcore/core-config.yaml` first for the app name, size, kind and phase.
- On activation, say who you are and print the command table below once. `*help` prints it again.
- Every task begins with `bash .tfcore/utils/tf-phase.sh start <command> <App>` and ends with the status gate (`.tfcore/tasks/_status-update-gate.md`) and one run record.
- A request in plain words maps to the nearest command: "fix these bugs" is `*fix-issues`, "log these bugs, do not fix" is `*triage-issues`, "you missed this" is `*log-miss`, "how is it going" is `*metrics`. When two could apply, ask which, once.

## Standing rules

Each rule lives in one place; these lines only point at it.

- Everything the owner reads is plain, simple English, a question for the owner goes in `docs/{App}-Decision-Request.md` rather than into the conversation, and an upstream defect is always filed — answering "Blocks: yes|no" first, and never stopping the run when the answer is no: `.tfcore/tasks/_owner-language.md`.
- Run to completion in YOLO or goal mode: `.tfcore/tasks/_yolo-mode.md`. `*build-phase` is in it by default.
- Run the application yourself and never ask the owner to boot or test anything: `.tfcore/tasks/_smoke-test-policy.md`, with `bash .tfcore/utils/tf-build.sh` for building on any host.
- A smoke is not a verify. `Verified` is written only by an executed `*verify`; the hook refuses it otherwise. Your ceiling as a builder is `Implemented`.
- Analyse is not fix. A bug reported without a request to fix it is `*triage-issues`, documents only. Code changes come only from `*build-phase` and `*fix-issues`.
- A miss is a record. When the owner says something was missed, `*log-miss` writes it to the miss stream in seconds. Never argue, never guess who caused it; the emitter resolves that.
- Git is manual and the hook refuses it. Evidence is the checklist and the files on disk.

## How it works

- A command starts with `*`. Each maps to one task file under `.tfcore/tasks/`; read that file when the command is typed, not before. Read `.tfcore/core-config.yaml` first for the app name, size, kind and phase.

## Standing rules

Each rule lives in one place; these lines only point at it.

- Everything the owner reads is plain, simple English, a question for the owner goes in `docs/{App}-Decision-Request.md` rather than into the conversation, and an upstream defect is always filed — answering "Blocks: yes|no" first, and never stopping the run when the answer is no: `.tfcore/tasks/_owner-language.md`.

## Claude

It's a problem with one of our own tests, not with the library. It doesn't affect anyone who uses TechieRag, and it can't block a release. The only effect is an occasional false failure when you run all the tests on your machine.

**What the test does** [Certain, from the code]
REQ-FN-006 checks that Sevak uses the published TechieRag packages rather than reaching into this repo's source. To check that, it looks for every project file in the Sevak folder next to this one. It asks .NET for all `*.csproj` files under the whole Sevak folder, and only afterwards throws away the ones in `bin` and `obj`.

So before filtering anything, it walks every folder in Sevak, including the large ones that hold nothing useful to it:
- build output (`bin`, `obj`)
- verify run leftovers in `tests/.artifacts`, such as a saved Sevak app with its WebView2 browser cache, thousands of small files

That takes about 30 seconds and a fair amount of memory.

**How it affects you**
- **Running all the tests at once on your machine:** the local-model tests use most of WSL's memory at the same time. Twice today, this test then failed with "Cannot allocate memory" while walking Sevak's cache folders. Both times it passed when re-run alone. So you can see a red result that isn't a real problem, and the test-run tool reports a failure.
- **The verifier:** if that false failure lands in a verify run, it could mark REQ-FN-006 as failing, and someone would spend time chasing it.
- **Releases:** no effect. The GitHub workflows have no Sevak folder next to the repo, so this test skips itself there.
- **People using TechieRag:** no effect. It's test code, not part of the package.

**The fix**
Skip `bin`, `obj` and `.artifacts` while walking, instead of after. The test then reads only a few dozen folders, finishes in about a second, and stops failing when memory is tight. It checks exactly the same thing as before. It's a few lines in `tests/TechieRag.Tests/LibraryDocumentationAcceptanceTests.cs`.
