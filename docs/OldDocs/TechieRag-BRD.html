1. Executive summary#

TechieRag is a configurable Retrieval-Augmented Generation (RAG) library for .NET, shipped as NuGet packages. It lets a .NET developer add document search, retrieval, and LLM-powered question-answering to an application with a few lines of fluent configuration — and switch embedding providers, vector stores, document formats, and LLM backends by configuration, not code. The library abstracts six embedding providers, three vector stores, nine document formats, and six LLM providers behind a single ITechieRag surface.

The product exists to eliminate the repetitive, tightly-coupled RAG plumbing that every .NET team rebuilds, and to offer a genuinely offline option (TechieRag.Embedded) using a bundled BGE-M3 ONNX model so data never has to leave the machine. A companion Blazor Server application — TechieDesk (formerly TechieRagWeb; renamed 2026-07-17 per BRD-82 / REQ-UI-014) — showcases every capability end-to-end and is being productized as a self-hostable AnythingLLM alternative (BRD-81), and an MSBuild "autodistribution" mechanism ships AI-agent skill files into any consuming repo so tools like Claude Code and OpenCode gain a /techierag assistant automatically.

As of this snapshot the library is ~96% complete: the v1.1 core (config, vector stores, processors, embeddings, sample app, Qdrant admin) and the v2 LLM layer (6 providers, auto-RAG, agent loop, token tracking, resilience, memory, 7 new sample pages) are all shipped and validated by manual/integration testing. The remaining work is a formal automated test suite and optional OpenTelemetry exporters. Repositioned 2026-07-17: the companion app is now TechieDesk, a productized, self-hostable AnythingLLM alternative powered by the TechieRag library; the competitive roadmap lives in docs/TechieRag-CompetitorAnalysis.md (GAP-LIB-/GAP-APP- register), with phase-wise BRD-Ns appended as each phase is scheduled.

Amended 2026-09-03 (owner decision) — three packages, one separate product. The library becomes three NuGet packages: TechieRag (retrieval, ingestion, providers, the dependency-free agent loop), TechieRag.Embedded (offline embeddings), and the new TechieRag.Agents — an agent layer on Microsoft Agent Framework (MAF) 1.20 with an agentic retrieval contract that lives in core (BRD-83…86). TechieDesk leaves this repository (BRD-87): it becomes a separate product in its own repository that consumes all three packages from NuGet exactly as any customer does, and is the live implementation of their capabilities. Consequently the library's requirements are ledgered here again from 2026-09-03 — the 2026-07-17 "single checklist in the TechieDesk BRD" arrangement is reversed — and the TechieDesk BRD keeps app requirements only.

Amended 2026-09-24 (owner decisions, docs/TechieRag-Update-Brief.md) — the library goes where the app goes, with or without the cloud. Four demands arrived together and are folded in here. (1) TechieDesk is renamed Sevak and the separation happened on 2026-09-24: Sevak is the application showing the full capabilities of TechieRag, freemium with limited rather than gated features, in its own private repository until its v0.1 (BRD-87 amended). (2) F-PLATFORM (BRD-88…95): TechieRag and TechieRag.Embedded work inside .NET MAUI apps on Windows, macOS (Mac Catalyst), Android and iOS — writable model folders, packaged native wiring, a small default model on phones, a probe app on all four heads. 2. Business objectives#

  • Reduce the cost of adding RAG to a .NET app from "a multi-project integration effort" to "one NuGet reference + fluent config".
  • Make provider choice (embedding / vector store / LLM) a configuration concern, swappable with zero code changes.
  • Offer a fully offline, privacy-preserving RAG path for air-gapped / on-premises / edge scenarios.
  • Support the breadth of real document formats (9) and LLM backends (6) so the library fits existing infrastructure rather than dictating it.
  • Ship production concerns — logging, telemetry, token budgeting, retry/circuit-breaker, fallback — in the box.
  • Guarantee backward compatibility (v1 → v2 additive) so upgrades never break consumers.
  • Run inside the consumer's own app on Windows, macOS, Android and iOS, including a language model that needs no server and no network after one download (added 2026-09-24, F-PLATFORM / F-LOCAL-LLM).
  • Let an end user bring their own hosted-vendor subscription to the app through a browser sign-in instead of pasting a pay-per-call API key, wherever the vendor permits it (added 2026-09-24, BRD-112…114).

3. Scope#

In scope:

  • The TechieRag core library: ingestion, processing/chunking, embedding, vector storage, semantic search, and (v2) LLM generation, agent loop, memory, token tracking, resilience.
  • The TechieRag.Embedded package: offline BGE-M3 ONNX embedding.
  • The TechieRag.Agents package (added 2026-09-03): agents on Microsoft Agent Framework over TechieRag — fluent builder, agentic retrieval context provider, and public interop adapters at the library's ILlmProvider / IToolHandler / IProgress<AgentStep> / IConversationMemory seams (BRD-84, BRD-85). The agentic retrieval contract itself (tool description, schema, structured result, instructions) lives in core with zero packages (BRD-83).
  • The TechieDesk Blazor Server application (formerly TechieRagWeb) — demonstrates all library features (incl. Qdrant administration) and is being productized as a self-hostable AnythingLLM alternative (BRD-81/BRD-82; roadmap in docs/TechieRag-CompetitorAnalysis.md). (Transferred 2026-09-03, BRD-87: TechieDesk is a separate product in its own repository and consumes the three packages from NuGet. Its requirements live in the TechieDesk BRD. The delivered F-WEB / F-QDRANT items below stay as historical record.)
  • NuGet packaging/publishing (three packages, two feeds) and AI-agent skill autodistribution.
  • Repository separation (added 2026-09-03, BRD-87; executed 2026-09-24): this repository holds library and library-test projects only. The application is Sevak (TechieDesk renamed), in its own repository.
  • The TechieRag.Local package (added 2026-09-24, BRD-96…109): an in-process local language model behind the same ILlmProvider, on Windows, macOS (Mac Catalyst), Android and iOS. Weights are downloaded once, never packed.
  • Platform support inside .NET MAUI apps (added 2026-09-24, BRD-88…95): writable model folders, packaged native wiring, a small default embedding model on phones, a probe app on all four heads, and a published support matrix.
  • Subscription sign-in providers (added 2026-09-24, BRD-112…114): a browser or device-code sign-in that yields an ILlmProvider billed to the user's own vendor subscription, for every vendor whose terms permit it.

Out of scope (explicit, per v2 spec §1.4; revised 2026-07-17 per CompetitorAnalysis):

  • Model fine-tuning / training.
  • Image / video generation.
  • Formal RAG-evaluation tooling (precision/recall harnesses).
  • Model hosting / inference-server provisioning (TechieRag consumes providers, it does not host them). Clarified 2026-09-24: running a model in-process inside the consumer's app (TechieRag.Local, F-LOCAL-LLM) is in scope; standing up or managing a model server (Ollama, vLLM, LM Studio, a cloud deployment) stays out.
  • Enforcing a vendor's terms of use on subscription sign-in (added 2026-09-24): the library records each vendor's stated terms in its connector catalog and offers no method where a vendor offers no flow; whether a given sign-in is personal or team use is decided by who signs in and what licence they hold, in the consuming app.
  • The Sevak product itself (TechieDesk until 2026-09-24) (from 2026-09-03): its screens, app services, packaging and app-side verification are specified and tracked in the Sevak repository. This BRD covers only what Sevak consumes. A Sevak requirement is referenced from here as Sevak#REQ-FN-054; a TechieRag requirement from there as TechieRag#REQ-RAG-054 (rule added 2026-09-24).

Formerly out of scope — moved to the roadmap 2026-07-17 (docs/TechieRag-CompetitorAnalysis.md, Phases 5–6):

  • Multi-agent orchestration (graphs / handoffs / guardrails — GAP-LIB-13).
  • Audio: TTS/STT abstractions and audio-file transcription ingestion (GAP-LIB-10/16).

9. Feature catalog#

F-ING: Document ingestion & processing#

Personas: .NET developer, knowledge-base builder · Phase: v1.1

Extracts text from nine document formats and splits it into overlapping semantic chunks ready for embedding. Content can be ingested from a single file, a directory (with a glob pattern), or raw text (for database/API content with no file). Each document carries optional metadata for later filtering.

API surfaceSignatureDescription
Ingest fileIngestAsync(filePath)Auto-routes by extension to the right processor
Ingest directoryIngestDirectoryAsync(path, pattern)Batch ingest with glob
Ingest textIngestTextAsync(text, name, metadata?)No file required
ChunkingWithChunkSize(size, overlap)Default 500 / 50 chars
LifecycleListDocumentsAsync, DeleteDocumentAsync, GetStatsAsync, ClearAsyncManage ingested corpus

Processors: PDF (PdfPig), DOCX (OpenXml), Markdown (Markdig), HTML (HtmlAgilityPack), JSON, TOML (Tomlyn), Code (70+ extensions), Text, Generic (binary-detection fallback).

F-PLATFORM: TechieRag inside .NET MAUI apps on four platforms#

Personas: MAUI app developer (MyDiary, Sevak), mobile developer · Phase: v5 · Added: 2026-09-24 (owner decision; plan 08 step 1)

The libraries target plain net10.0 and load on Android and iOS by fallback, but nothing today makes them work there: model folders default to AppContext.BaseDirectory (read-only on phones), the Mac Catalyst / iOS native ONNX wiring lives only in the app's csproj, the default embedding model is a 2.3 GB download, and SqliteVecStore runs a managed full scan because sqlite-vec is never loaded. F-PLATFORM fixes each of these in the package so every consuming app receives them, and proves it with a probe app built on all four heads. The earlier "mobile app: do not build" line in docs/TechieRag-CompetitorAnalysis.md was about a mobile application; a library that works inside mobile applications is this feature.

Amended 2026-09-24 — two contract additions (owner decisions, docs/TechieRag-Update-Brief.md decisions 8 and 9). Streaming with tool calls (BRD-110, BRD-111): today a caller must choose between ChatStreamAsync (text only) and ChatAsync (tool calls, no streaming). A new streaming method yields typed events — a text delta, a decided tool call, a final usage record — so a tool-using turn streams. It is additive: ChatStreamAsync stays and is implemented on top of it, so no consumer breaks and no major version is needed. It lands before TechieRag.Local exists, so the seventh provider implements the final contract once. Subscription sign-in (BRD-112…114): the host app drives the browser or device-code step; the library returns the URL and code, waits, and yields an ILlmProvider billed to the user's subscription. Vendor terms are facts recorded in LlmConnectorCatalog, not rules enforced in code: at 2026-09-24 OpenAI permits this in external tools for personal use and Anthropic prohibits it for Free/Pro/Max plans; Google, Groq, xAI and Meta are researched before build (BRD-114).

F-LOCAL-LLM: TechieRag.Local package — in-process local language model#

Personas: privacy-first app developer (MyDiary: "no cloud inference path at all"), Sevak offline user, edge developer · Phase: v5 · Added: 2026-09-24 (owner decision; plan 08 step 4; closes MyDiary feedback TR-RAG-001)

Embeddings already have an offline path (TechieRag.Embedded); completions do not: Ollama and LM Studio need a server process that cannot run inside an iOS or Android sandbox, and the other four providers are cloud APIs. TechieRag.Local is a fourth package, never part of core, that runs a small language model inside the app process. The consumer sees one builder call, UseLocalLlm(), and one ILlmProvider that behaves identically on Windows, macOS (Mac Catalyst), Android and iOS. Underneath, an internal runtime interface has one implementation per platform, chosen after a measured comparison (LLamaSharp / llama.cpp with GGUF models against ONNX Runtime GenAI) recorded in DECISIONS.md; a later backend such as an operating system's built-in model fits behind the same interface. Weights are downloaded once to the per-user app data folder from F-PLATFORM, after the user accepts the model's terms, and are never inside the package or the app bundle. Sevak is the first desktop consumer; MyDiary the first mobile one.

12. Constraints & assumptions#

  • Target runtimes are net10.0 and net8.0 for TechieRag, TechieRag.Telemetry and TechieRag.Agents; TechieRag.Embedded is net10.0 only (amended 2026-09-03; was "net10.0").
  • Local providers (Ollama, LM Studio) and external stores (PostgreSQL, Qdrant) must be reachable when selected; cloud providers require the consumer's own API keys.
  • The embedded model requires a one-time ~2.3GB download and sufficient local disk + CPU/GPU for ONNX inference.
  • The TechieDesk app (folder apps/TechieDesk, renamed per BRD-82) depends on TrBlazeUI.* from GitHub Packages, which requires an authenticated nuget.config token to restore. (Moved with TechieDesk 2026-09-03, BRD-87. The library packages restore from nuget.org alone.)
  • TechieRag.Agents depends on Microsoft.Agents.AI 1.20.0, Microsoft.Extensions.AI 10.9.0 and Microsoft.Extensions.AI.OpenAI 10.9.0; the last pins the OpenAI SDK to 2.12.x, which restores cleanly beside core's Azure.AI.OpenAI 2.1.0 (open upper bound) but unifies the SDK version in any consumer that references both packages (added 2026-09-03).
  • Model-facing text in the library (tool descriptions, agent instructions) is invariant English by policy; consumers localize only user-facing output (added 2026-09-03).
  • The codebase uses standard Microsoft camelCase naming (no obj/a/v prefixes, no underscores) — recorded in Coding-Standards.
  • TechieRag.Local depends on a native inference runtime chosen per platform after a measured comparison (LLamaSharp / llama.cpp or ONNX Runtime GenAI, or one of each); the choice is recorded in DECISIONS.md with the numbers before the provider is built, and is costly to reverse (added 2026-09-24).
  • On Android and iOS the app bundle is read-only and memory is limited: model and cache files live in the per-user application data folder, default embedding models are small, and a model that does not fit is refused rather than loaded (added 2026-09-24).
  • Subscription sign-in depends on each vendor's policy, which vendors change; the connector catalog records the policy and the date it was checked, and the library never asserts a permission it has not verified against live documentation (added 2026-09-24).
  • Real-device runs (a Mac, an Android phone, an iPhone) are the owner's; simulators hide memory limits and native-library problems, so a platform cell in the support matrix counts as tested only from a named device (added 2026-09-24).

  • Breadth: 6 embedding providers, 3 vector stores, 9 formats, 6 LLM providers supported.

15. Glossary#

  • RAG — Retrieval-Augmented Generation: retrieve relevant context, then generate an answer with an LLM.
  • Sevak — The application showing the full capabilities of TechieRag; TechieDesk renamed on 2026-09-24, in its own repository.
  • In-process local model — A language model executed inside the consuming app's own process by TechieRag.Local, with no server and no network after a one-time download (added 2026-09-24).
  • GGUF / ONNX Runtime GenAI — The two model-file-and-runtime families compared for TechieRag.Local: GGUF files run by llama.cpp (LLamaSharp in .NET); ONNX files run by Microsoft's ONNX Runtime GenAI (added 2026-09-24).
  • Device-code sign-in — A browser sign-in where the library shows a URL and a short code, the user signs in on the vendor's site, and the library receives a token billed to the user's subscription (added 2026-09-24).
  • Typed streaming event — One piece of a streamed reply: a text delta, a decided tool call, or the final usage record (BRD-110) (added 2026-09-24).
  • TechieRag — this library; the core NuGet package.
  • TechieRag.Embedded — the offline variant bundling a BGE-M3 ONNX embedding model.
  • TechieDesk — the desktop product (formerly TechieRagWeb): since 2026-09-03 a separate repository that consumes the three TechieRag packages and is the live implementation of their capabilities (BRD-81/82/87).
  • TechieRag.Agents — the third package: agents on Microsoft Agent Framework over TechieRag, with seam adapters (BRD-84/85).
  • MAF — Microsoft Agent Framework (Microsoft.Agents.AI), the successor to Semantic Kernel Agents and AutoGen; ChatClientAgent, AgentSession, AIContextProvider.
  • MEAI — Microsoft.Extensions.AI: IChatClient, AITool / AIFunction, FunctionInvokingChatClient; the abstractions MAF is built on.
  • TrBlazeUI — the Blazor UI component library used by TechieDesk.
  • Embedding — a vector representation of text used for similarity search.
  • Vector store — a database that indexes and similarity-searches embeddings (SQLite-vec / pgvector / Qdrant).
  • REQ-UI-/REQ-FN-/REQ-RAG-/REQ-NFR- — implementation requirement IDs derived from BRD-N in the split checklists.
